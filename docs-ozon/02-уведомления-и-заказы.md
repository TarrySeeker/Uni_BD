# Ozon Acquiring — уведомления, сценарии, createOrder

## Подпись уведомления (входящий вебхук)
Формат ДРУГОЙ, чем у запроса: значения через разделитель "|", ключ — notificationSecretKey.
SHA-256 в hex.

- Уведомление о попытке оплаты ЗАКАЗА:
  SHA256("{accessKey}|{orderID}|{transactionID}|{extOrderID}|{amount}|{currencyCode}|{notificationSecretKey}")
- Уведомление о статусе САМОСТОЯТЕЛЬНОЙ попытки оплаты:
  SHA256("{accessKey}|||{extTransactionID}|{amount}|{currencyCode}|{notificationSecretKey}")

Поля: transactionID может быть пустым (тогда transactionUid); extOrderID может быть пустым
для оплаты заказа, обязателен для самостоятельных оплат.

Контрольный пример (ПРОВЕРЕН, сходится):
digest = 1fac5a70-0ec4-4963-a33a-040ea301ea85|69f37767-8a8b-4de1-a601-384387aea8c4|6981437||52569|643|4qEzUJjBoCXwA6P5NMyrJJUdA6xsnvbV
signature = ae3c635dd72ec6b2c7833aa7458d57827895a57d4c35fba0e7dcb48f1d367d5f

⚠️ amount в примере = 52569 при currencyCode 643 — похоже на КОПЕЙКИ (525,69 ₽). Уточнить.

## Сценарии интеграции
1. Ozon Pay Checkout — готовая платёжная форма. Способы: банковская карта, СБП, Ozon Карта,
   авторизация по Ozon ID. Режимы заказа: полный (MODE_FULL, состав корзины) и
   сокращённый (MODE_SHORTENED, одна позиция).
2. Самостоятельная интеграция — оплата ТОЛЬКО через СБП.

→ Для tvuchet.ru берём Ozon Pay Checkout (нужна оплата картой), режим MODE_FULL,
   редирект на payLink. НЕ «самостоятельную интеграцию» — там только СБП.

## Порядок работы с заказами
- /v1/createOrder — создать. paymentAlgorithm: PAY_ALGO_SMS (одностадийный) |
  PAY_ALGO_DMS (двухстадийный, подтверждение по позициям).
  fiscalizationType: FISCAL_TYPE_SINGLE (нужна маркировка для needMark=true) | FISCAL_TYPE_DOUBLE.
  Валюта только 643 (рубль). В ответе order.items.positions — позиции с id, они нужны
  для confirmOrder / createFinalReceipt / refundOrder.
- /v1/updateOrderPositions — внести/изменить маркировку.
- /v1/getOrderStatus — статус по id (эквайринг) или extId (магазин).
- /v1/getOrderDetails — детали; данные о платёжной операции только для оплаченного.
- /v1/cancelOrder — отмена, ТОЛЬКО в статусе STATUS_PAYMENT_PENDING.
- /v1/confirmOrder — подтверждение для DMS. Без ручного подтверждения система сама
  подтвердит через 5 дней. Неподтверждённая сумма возвращается покупателю.
- /v1/createFinalReceipt — финальный чек при двойной фискализации.
- /v1/refundOrder — возврат в статусах STATUS_PAID, STATUS_PARTITIONAL_REFUND, STATUS_AUTHORIZED.

## createOrder — тело запроса
Обязательные: accessKey, amount{currencyCode,value}, paymentAlgorithm.
Прочие: extId (уникален; повторный вызов с тем же extId вернёт РАНЕЕ созданный заказ — удобно
для идемпотентности), expiresAt, mode, items[], successUrl, failUrl (обязательны, если нет
значения по умолчанию в настройках токена), notificationUrl, requestSign, receiptEmail,
fiscalizationPhone, enableFiscalization, fiscalizationType, deliverySettings.isEnabled, extData.

items[]: name, price{currencyCode,value}, quantity, type (TYPE_PRODUCT), vat (VAT_0 и др.),
extId, sku, needMark, attributes, positions[].mark.

## Ответ createOrder
order.id — идентификатор на стороне эквайринга
order.payLink — ССЫЛКА НА ОПЛАТУ (редиректим покупателя сюда)
order.status — STATUS_NEW и т.д.
order.number, order.isTestMode, order.remainingAmount, order.items[].positions[].id
